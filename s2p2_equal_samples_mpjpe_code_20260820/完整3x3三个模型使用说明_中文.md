# MM-Fi 完整 3×3 三模型重训说明

更新时间：2026-08-21

> 日常运行优先进入项目根目录 `launchers\` 使用编号 CMD。本文保留底层 runner
> 的完整调用方式，适合单格、自定义超参数和问题排查。当前活动代码目录是
> `s2p2_equal_samples_mpjpe_code_20260820`，旧 `20260818` bundle 仅供归档追溯。

## 1. 实验范围

本入口用于完整的：

- 协议：`P1 / P2 / P3`
- 划分：`S1 / S2 / S3`
- 模型：`MetaFi++ / HPE-Li / DT-Pose`
- 随机种子：`0 / 1 / 2`

因此默认三个模型、三个 seed、九个格子一共是：

`3 × 9 × 3 = 81` 次独立训练。

程序按模型和 seed 顺序执行，不会在一张 5090 上并行启动多个训练。

本文件对应的入口是：

`cloud_rerun/run_3x3_equal_samples_three_models.py`

旧的 `run_s2p2_equal_samples_three_models.py` 已随旧 bundle 归档，只负责历史
S2-P2 等样本重训，不是当前活动目录入口。

本次严格等样本实验必须分两阶段：

1. 先用 `run_dtpose_equal_samples_pretrain.py` 为九个格子各生成一份新的
   DT-Pose CSI 预训练权重；
2. 再用 `run_3x3_equal_samples_three_models.py` 执行三个模型、九个格子、三个
   seed 的 81 次姿态训练。

旧 bundle 的 `pretrain_weights/` 是历史 DT-Pose 预训练结果，曾使用完整的原始帧
范围。它们仍保留在归档中，但严格等样本姿态训练不能直接混用，必须显式指定新的
预训练目录。

## 3. 先生成等样本 DT-Pose 预训练权重

### 3.1 预训练样本范围

姿态阶段使用每个动作片段的 target frame `idx=62..296`，共 235 个样本。
自监督预训练需要相邻帧，因此使用：

- 当前帧：`62..295`；
- 下一帧：`63..296`；
- 实际涉及的唯一 CSI 帧：仍然是 `62..296`。

这样预训练不会使用姿态阶段之外的 CSI 帧，同时保留最后一帧 `296` 作为下一帧目标。
每个动作序列预训练有 234 个当前帧/下一帧训练对。

预训练仍使用原 DT-Pose 的自监督逻辑和参数：`mask_ratio=0.80`、400 epochs、
配置 batch size `4096`、单卡 micro-batch `256`、梯度累积 16 次、base LR
`1.5e-4`、按 batch 缩放后的 AdamW 初始学习率 `0.0024`、seed `42`。本阶段只
生成 9 份 encoder 权重，不会启动 MetaFi++、HPE-Li 或姿态训练。

预训练入口：

`cloud_rerun/run_dtpose_equal_samples_pretrain.py`

## 6. 完整启动 81 次姿态训练

确认 dry-run 无误后，再执行正式命令。输出目录必须使用一个尚不存在的新目录：

```cmd
"C:\Users\CHEN\.conda\envs\bit\python.exe" -u cloud_rerun\run_3x3_equal_samples_three_models.py --project_root "D:\study\four_grade\graduation_article\data_pdf\MMFi_Dataset\s2p2_equal_samples_mpjpe_code_20260820" --dataset_root "D:\study\four_grade\graduation_article\data_pdf\MMFi_Dataset\data_base" --dtpose_pretrain_root "D:\study\four_grade\graduation_article\data_pdf\MMFi_Dataset\strict_offline_runs\dtpose_equal_samples_pretrain_20260821_01" --output_root "D:\study\four_grade\graduation_article\data_pdf\MMFi_Dataset\strict_offline_runs\three_baselines_equal_samples_3x3_mpjpe_20260821_01" --all_cells --models metafi hpeli dtpose --seeds 0 1 2 --num_workers 8 --eval_num_workers 8
```

训练是串行的。每一个 run 都会：

1. 写入自己的 `config.yaml`；
2. 写入自己的 `launcher.log` 和训练日志；
3. 按 validation MPJPE 最低的 epoch 选择 checkpoint；
4. 将该同一个 epoch 的模型同时保存为 `pose_mpjpe.pt`、`pose_pampjpe.pt` 和 PCK 文件；
5. 在 `selection.json` 写明 `selection_metric: mpjpe`。

这里的 validation 指对应格子的验证集，不是独立 official test performance。

## 9. worker 参数

默认使用：

```text
--num_workers 8 --eval_num_workers 8
```

如果 GPU 利用率低、CPU 和内存有余量，可以把两个数一起改为 12 或 16，例如：

```cmd
--num_workers 12 --eval_num_workers 12
```

不要盲目调得很大。Windows 多进程 DataLoader 会额外占用内存；如果出现卡顿、内存不足
或 worker 崩溃，退回 8。worker 数只影响数据加载，不改变模型结构和指标口径。

## 10. 九格样本数核对

姿态训练所有格子的有效 target frame 都是 `idx=62..296`，每个动作序列 235 个样本。
等样本 DT-Pose 预训练使用 `62..295` 的当前帧和 `63..296` 的下一帧，每个动作
序列 234 对；它们涉及的唯一 CSI 帧仍是 `62..296`。

| 格子 | 训练样本 | 验证样本 |
|---|---:|---:|
| P1-S1 | 105,280 | 26,320 |
| P2-S1 | 97,760 | 24,440 |
| P3-S1 | 203,040 | 50,760 |
| P1-S2 | 105,280 | 26,320 |
| P2-S2 | 97,760 | 24,440 |
| P3-S2 | 203,040 | 50,760 |
| P1-S3 | 98,700 | 32,900 |
| P2-S3 | 91,650 | 30,550 |
| P3-S3 | 190,350 | 63,450 |

S1 按官方 loader 的 action-wise random split 生成，固定 `random_seed=0`；不要把它
简化成固定验证受试者。S2 是 cross-subject，S3 是 cross-scene。

## 11. 命令行超参数覆盖

姿态 3×3 runner 支持在命令末尾直接覆盖本次所选模型的公共参数：

```text
--batch_size 32
--max_device_batch_size 32
--lr 1e-3                 （也可以写 --learning_rate）
--epochs 60               （也可以写 --total_epoch）
--num_workers 12
--eval_num_workers 12
```

例如只跑 MetaFi++ 的完整 3×3，并使用自定义参数：

```cmd
"C:\Users\CHEN\.conda\envs\bit\python.exe" -u cloud_rerun\run_3x3_equal_samples_three_models.py --project_root "D:\study\four_grade\graduation_article\data_pdf\MMFi_Dataset\s2p2_equal_samples_mpjpe_code_20260820" --dataset_root "D:\study\four_grade\graduation_article\data_pdf\MMFi_Dataset\data_base" --output_root "D:\study\four_grade\graduation_article\data_pdf\MMFi_Dataset\strict_offline_runs\metafi_3x3_custom_20260821_01" --all_cells --models metafi --seeds 0 1 2 --batch_size 32 --max_device_batch_size 32 --lr 1e-3 --epochs 60 --num_workers 12 --eval_num_workers 12
```

覆盖值会写入每个 `config.yaml` 和 `manifest.json`。同一条命令选择多个模型时，
覆盖值对所有所选模型相同；若每个模型需要不同参数，应分别执行三条命令。

`batch_size` 是配置中的目标 batch，`max_device_batch_size` 是单卡 micro-batch。
当前历史 `train_pose.py` 的 `step_count` 没有递增，因此每个 micro-batch 都会更新。
DT-Pose 默认虽配置 `32/16`，实际更新 batch 是 16。上面的自定义示例设置
`32/32`，所以实际更新 batch 才是 32。若要严格复现历史结果，保持各模型默认值。

DT-Pose 等样本预训练 runner 也可以直接覆盖：

```text
--batch_size
--max_device_batch_size
--mask_ratio
--lr 或 --base_learning_rate
--weight_decay
--warmup_epoch
--epochs 或 --total_epoch
--num_workers
```

预训练的 `--base_learning_rate` 仍会在原始 `pretrain.py` 中按
`batch_size / 256` 缩放为 AdamW 的实际初始学习率。

## 12. 源码和权重保护

启动器不会修改三套模型源码。训练前会检查：

- `model/metafi/` 下 MetaFi++ 文件；
- `model/hpeli/` 下 HPE-Li 文件；
- `model/model.py` 和 `model/utils/` 下 DT-Pose 文件；
- 九份与格子一一对应的 DT-Pose ratio80 预训练权重。

对应的清单是：

- `model_source_hashes.json`
- `dtpose_pretrain_source_hashes.json`
- 等样本预训练输出根目录中的 `pretrain_source_hashes.json`

任一文件被改动、缺失、替换或权重映射不一致，程序会在训练前退出。
