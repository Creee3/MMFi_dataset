# 源模型完整性核验

更新时间：2026-08-21

## 结论

当前活动目录 `s2p2_equal_samples_mpjpe_code_20260820` 没有重新修改
`model/` 下的模型文件。它的 8 个模型源文件与之前正式云端实验使用的
`metafi_s2p2_cloud_bundle_20260817/model/` 逐字节一致，`model_source_hashes.json`
记录了 SHA-256；启动器在训练开始前会再次核验这些 hash。

因此，本次等样本重跑改变的是实验适配层：

- `feeder/mmfi.py` 增加 target frame `62..296` 的筛选，并允许关闭未使用的 next-frame 读取。
- `feeder/mmfi.py` 增加可调的 `num_workers`、`pin_memory` 和预取设置。
- `train_pose.py` 增加 worker、独立输出目录和 MPJPE checkpoint 选择配置。
- `cloud_rerun/` 只负责生成配置、检查数据和顺序启动三个模型。

相对于旧正式云端 bundle，模型结构、`forward`、训练损失实现和模型参数文件
没有在当前活动包中改写。这里的“没有改写”是指本次等样本重跑没有再次动它们；
`train_pose.py` 本身仍然是旧正式云端训练器的副本，并不等同于原作者仓库的
最初训练脚本。

## 与本地原始 DT-Pose 的差异

本地保存的原始代码位于：

`资料收集/MMFi_recent_code/DT-Pose-main/model/`

将它与正式云端 bundle 对比后，确实存在几处更早就已经存在的兼容性差异，
它们不是本次等样本重跑新引入的：

1. `model/model.py` 中邻接矩阵的设备写法由 `feature.device` 改为
   `img.device`。两者在当前前向路径中位于同一设备上，属于设备兼容写法，
   不改变网络层、参数或张量计算结构。
2. `model/hpeli/hpeli.py` 和 `model/metafi/mynetwork.py` 去掉了未使用的
   `xxsubtype` 导入，并将未使用的 `cv2` 改为可选导入。这是为了适配云端
   Python 环境；当前 CSI 前向路径不调用这些对象。
3. `mynetwork.py` 末尾有一段被三引号包住的备用初始化函数，因此不会执行；
   它不参与正式训练。

这些差异在 566、762、823 等已归档的云端快照中也一致存在，且旧正式 bundle
与当前活动包的模型 hash 完全相同。换句话说：本次没有把本地原始源码偷偷改成
另一套模型，但正式云端版本本身与原始仓库版本需要按上述差异记录。

此外，旧正式训练器相对原始 DT-Pose 训练脚本还保留了历史实验约定，例如
CSI 姿态训练的正式学习率、MSE 训练损失、日志/权重保存方式和 checkpoint 选择
逻辑。本次为了和之前正式结果可比，继续沿用这些约定；它们属于训练器配置和
实验协议，不是本次对 `model/` 网络结构的临时改动。

需要单独记录：姿态训练器中的 `step_count` 没有递增。DT-Pose 虽配置 batch 32、
micro-batch 16，实际每个 micro-batch 都执行一次优化器更新，因此实际更新 batch
是 16。该历史行为没有在当前整理中修复；网络源码 hash 也不用于掩盖这一训练器
口径差异。

## 如何复核

从项目根目录 `launchers\` 运行 `00_verify_all.cmd` 时，会检查：

- `model/` 文件清单是否多出或少了文件；
- 每个模型源文件的 SHA-256 是否与 `model_source_hashes.json` 一致；
- 九个格子的训练和验证样本数；其中 S2-P2 应分别为 `97,760` 和 `24,440`；
- DT-Pose 九格预训练的样本范围和入口源码。

任意一项失败都会在训练前停止，不会覆盖旧实验目录。
