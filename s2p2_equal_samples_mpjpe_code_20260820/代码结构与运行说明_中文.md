# 三模型等样本 3×3 代码结构与运行说明

更新时间：2026-08-21

这份文件对应目录：

`s2p2_equal_samples_mpjpe_code_20260820`

它是 5090 当前使用的三个 baseline 活动代码包。日常启动优先使用项目根目录
`launchers\`；本文件用于解释底层结构和直接调用方式。PrivPose 仍使用项目根目录
自己的主线，不包含在这个 baseline runner 中。

### 训练调用关系

```text
3×3 runner
    └── train_pose.py
          ├── model/metafi/   -> MetaFi++
          ├── model/hpeli/    -> HPE-Li
          └── model/model.py  -> DT-Pose

DT-Pose 预训练 runner
    └── pretrain_equal_samples_entry.py
          └── pretrain.py     -> MAE/CSI 自监督预训练
```

三个姿态模型共享 `train_pose.py`、`feeder/mmfi.py` 和指标计算代码，
但网络实现仍分别位于 `model/metafi/`、`model/hpeli/` 和 `model/model.py`。
共享训练入口不表示三个模型被合并了。

## 2. 是否改动了源模型

没有随意改写三个模型的网络结构、前向传播、损失函数或原始评估公式。
`model_source_hashes.json` 锁定了 8 个正式使用的网络源码文件；3×3 runner
在开始训练前会检查文件清单和 SHA-256，文件缺失、增加或内容变化都会停止。

有意保留的适配层改动只有以下几类：

1. `feeder/mmfi.py` 支持 `target_frame_start/end`、关闭 next-frame，并使用
   跨平台路径；这是为了让三个模型使用同一段 target-time 样本。
2. `train_pose.py` 支持 `num_workers`、`eval_num_workers`，并按配置的
   `checkpoint_selection` 选择 validation MPJPE 或 PA-MPJPE。
3. `cloud_rerun/` 只生成每个格子/模型/seed 的独立配置、记录 manifest、串行
   调用原训练入口，不复制或改写模型网络。

这些适配不是随机修改；原模型源码和历史结果仍保留在各自归档中。

## 3. DT-Pose 的“样本预训练”是什么

DT-Pose 是两阶段流程。预训练不是再次训练 3D 姿态，也不是额外的第四个模型。

1. `pretrain.py` 对 CSI 做 MAE 自监督学习：随机遮挡约 80% 的 CSI patch，
   学习 CSI encoder 的表示，并保存一个 encoder checkpoint。
2. `train_pose.py` 读取这个 encoder，在其上接姿态解码器，训练 17 个关节的
   3D 坐标回归。每个协议/划分格子使用对应的预训练 checkpoint；三个 pose
   seed 可以共享同一格子的 encoder checkpoint。

为了与姿态阶段的 target-time 样本完全对齐，等样本预训练使用：

- 当前帧：`idx=62..295`，共 234 帧；
- 下一帧：`idx=63..296`，共 234 帧；
- 唯一涉及的 CSI 帧：`idx=62..296`，没有超出姿态阶段范围；
- 每个动作序列：234 个当前帧/下一帧样本对。

姿态阶段每个动作序列有 235 个 target frame，因此预训练样本数会比姿态阶段
每个序列少 1 个，这是因为最后一帧只能作为 next-frame 目标，不能再作为当前帧。
代码会在启动前通过 `feeder.mmfi.decode_config()` 重新推导并核对数量，不是手工
写死后直接训练。

## 4. 每个模型能否单独跑完整 3×3

可以。完整 3×3 是 9 个格子；默认 3 个 seed，因此每个模型是 27 次姿态训练，
三个模型合计 81 次。三个模型按顺序串行运行，不会在一张 5090 上同时占用三份
显存。

日常运行可直接使用根目录 `launchers\11`、`12`、`21`、`23` 号脚本。需要单格
或自定义参数时，再在 PyCharm 的 **CMD** 终端设置以下变量并调用底层 runner：

```cmd

set "ROOT=D:\study\four_grade\graduation_article\data_pdf\MMFi_Dataset"
set "BUNDLE=%ROOT%\s2p2_equal_samples_mpjpe_code_20260820"
set "DATA=%ROOT%\data_base"
set "PY=C:\Users\CHEN\.conda\envs\bit\python.exe"
set "PYTHONPATH=%BUNDLE%;%ROOT%\_python_deps"
```

## 5. 命令行修改超参数

姿态 runner 支持以下覆盖项：

```text
--batch_size
--max_device_batch_size
--learning_rate 或 --lr
--total_epoch 或 --epochs
--num_workers
--eval_num_workers
```

例如，只对 MetaFi++ 的 3×3 运行改成实际更新 batch 32、micro-batch 32、学习率
`1e-3`、训练 60 epoch：

```cmd
"%PY%" -u cloud_rerun\run_3x3_equal_samples_three_models.py --project_root "%BUNDLE%" --dataset_root "%DATA%" --output_root "%ROOT%\strict_offline_runs\metafi_3x3_custom_20260821_01" --all_cells --models metafi --seeds 0 1 2 --batch_size 32 --max_device_batch_size 32 --lr 1e-3 --epochs 60 --num_workers 12 --eval_num_workers 12
```

不写覆盖项时，保留各模型默认值：MetaFi++ `16 / 16 / 1.85e-3`，HPE-Li
`16 / 16 / 1e-3`，DT-Pose `32 / 16 / 8.49e-4`，均为 50 epoch。

这些覆盖项会写进每个 `config.yaml` 和总 `manifest.json`。同一条命令中如果
同时选择多个模型，覆盖值会作用于所有被选模型；如果三个模型需要不同的超参数，
请分三条命令分别运行。

`batch_size` 是配置的目标 batch，`max_device_batch_size` 是单卡实际装入的
micro-batch。启动器会检查二者可整除。需要特别注意：历史 `train_pose.py` 中
保留了原来的 `step_count` 行为，当前代码没有擅自修复其梯度累积计数。因此
DT-Pose 的历史配置虽然写着 batch 32 / micro-batch 16，实际 optimizer step
会在每个 micro-batch 后发生，实际更新 batch 是 16。不能只看配置数字就声称
完成了标准 32 样本梯度累积。若要实际更新 batch 32，必须把两个参数都设为 32。

DT-Pose 预训练 runner 也支持：

```text
--batch_size
--max_device_batch_size
--lr 或 --base_learning_rate
--weight_decay
--warmup_epoch
--epochs 或 --total_epoch
--num_workers
```

其中预训练的 `--base_learning_rate` 是原代码中的 base LR，AdamW 实际初始
学习率还会按 `batch_size / 256` 缩放；这两个概念不要混写。

## 6. 结果和断点续跑

每个姿态 seed 独立保存 `config.yaml`、`launcher.log`、训练日志、
`selection.json` 和 checkpoint。当前 3×3 runner 按对应验证集的 **MPJPE 最低
epoch** 选择模型，并把该 epoch 的状态保存为 `pose_mpjpe.pt`、
`pose_pampjpe.pt` 和 PCK 文件。

中断后使用完全相同的参数和原来的输出目录，加 `--resume`；不要修改已有
`config.yaml`，也不要把新参数混进旧 manifest。

## 7. 运行前检查

不启动训练的核验命令：

```cmd
"%PY%" -u cloud_rerun\run_3x3_equal_samples_three_models.py --project_root "%BUNDLE%" --dataset_root "%DATA%" --all_cells --models metafi hpeli --seeds 0 1 2 --num_workers 8 --eval_num_workers 8 --verify_only
```

这条只选 MetaFi++ 和 HPE-Li，所以不会要求 DT-Pose 预训练目录。
选 `dtpose` 时必须额外给出 `--dtpose_pretrain_root`，并且该目录必须包含
等样本预训练 runner 生成的 `pretrain_source_hashes.json`。

不要在 CMD 中使用 PowerShell 的 `$env:PYTHONPATH` 或 `&`；本说明中的命令都是
PyCharm CMD 写法。
